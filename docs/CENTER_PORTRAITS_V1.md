# 兴趣中心画像与相近文献上下文 v1

日常运行仍先完成 latent-auto Top 20，然后准备 AI 上下文、质量判断、翻译和 RSS。

当质量判断启用为 LLM/JEV 且允许私人上下文时：

1. 使用已校验的本次 generation 与历史成员向量，按成员与中心的余弦相似度排序，每个正式中心取前 10 篇（不足 10 篇使用全部，但至少 5 篇）。标题最多 500 字符、可信摘要最多 2,500 字符。
2. 由 LLM 生成约 150–350 字的中文兴趣描述，涵盖核心问题、机制、方法和相邻方向。描述上限 1,200 字符。JEV 不承担此生成任务。
3. 描述绑定仓库、文库身份、interest_model_revision 与中心 ID。同一版本不重复生成；重算中心后首次启用判断时生成新画像。中断时逐中心保存成功结果，下次只生成缺失项。换判断 provider 或模型不会重新生成现有画像。
4. 对每篇候选用相同的冻结 MiniLM 编码，从其匹配中心的全部成员中检索余弦相似度最高的 3 篇，而不是重复使用固定中心代表文献。
5. 向选中的 LLM/JEV 提供候选标题、可信摘要（最多 3,000 字符）、期刊（最多 300 字符）、兴趣画像，以及这 3 篇相近文献的标题和摘要片段（最多 900 字符）。保持原来的质量排除、整批失败回退和原始顺序规则。

## LLM 连接

可在 `zotwatch-optional-ai.yaml` 顶层指定 `profile_service: deepseek`，引用已有非 JEV 服务。未指定时依次选择：LLM 判断连接、翻译连接（即使翻译关闭，仍可使用已选连接）、其他可用 LLM 服务。沿用连接模型及相应 route 的模型覆盖；画像生成与翻译开关独立。

仅配置 JEV 而没有可用 LLM 时，不生成虚构画像；AI 发布处理回退原 Top 20。画像生成、向量校验或邻居检索失败也采用该回退。失败的画像不缓存。生成画像最多每个正式中心一次请求（正式中心上限 60），后续无画像生成请求。

## 持久化和发布

`state/center-profiles-v1.json` 保存当前 generation 的私人画像；独立私有 Git 分支 `zotwatch-center-profiles-v1` 在每日执行前恢复、执行后通过非强制快进 CAS 保存。不会依赖可能被清除的 Actions cache，也不修改不可变 generation。

恢复失败时跳过可选 AI 发布，以免误认为画像缺失而重复计费。保存失败使工作流明确失败，避免宣称已持久化。成功生成的部分画像即使本轮判断回退也会尝试持久化。

工作流向 `zotwatch.staging_ai` 增加 `--encoder-cache`。公共 sidecar 仍只含允许发布的论文文本和保留列表，不包含画像、历史文献、相似度或判断理由。判断提示词版本已升级，避免复用旧上下文判断缓存。
